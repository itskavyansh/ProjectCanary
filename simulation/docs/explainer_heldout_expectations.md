# Pre-Registered Held-Out Negative Control Expectations for the Advisory Alarm Explainer (SYNTHETIC / SIMULATION)

**Status:** Pre-registered and committed **alone before any run** of the held-out negative-control suite (seed `20261125`, 36 new corrupted explanations across 6 previously unused corruption types + 42 untouched faithful controls, $N = 78$ total). `ExplanationGuard` v2 is frozen and will **not** be modified during or after this held-out evaluation.

---

## 1. Why a Held-Out Negative Control Is Required

`ExplanationGuard` v2 achieved `42 / 42` (`100.0%`) catch rate on the original 6 corruption types (`a_number_perturbed_10pct` through `f_unsupported_trend_claim`, seed `20261124`). However, because Guard v2's label-value binding and forbidden-trend-word rules were authored *after* observing Guard v1's failures on those exact corruption templates (`b_node_label_swap` and `f_unsupported_trend_claim`), `42 / 42` on the original corruptions is an in-sample regression check rather than independent out-of-sample evidence.

To obtain an honest out-of-sample estimate of what slips through Guard v2 versus the secondary LLM judge (`muse-spark-1.3`, separate verification prompt, never given `truth`), we construct **36 new corrupted explanations (`6 per type`, seed `20261125`)** from cached faithful explanations using **six corruption mechanisms NOT used in the first negative control**, evaluated alongside the **same 42 untouched faithful controls**:

1. **(i) `i_trend_metaphor_unlisted`**: Unlisted multi-word trend metaphors without any word from `forbidden_trend_regexes` (`"creeping upward"`, `"climbing progressively"`, `"gaining momentum"`).
2. **(ii) `ii_wrong_sensor_family`**: A valid packet number from one sensor family attached to a different sensor family (e.g., a node's mean tilt value in degrees described as piezo energy / piezo RMS).
3. **(iii) `iii_cross_sentence_node_number`**: A node named in one sentence and another node's numeric reading attributed to it across a sentence boundary via anaphora (e.g., `"Simulated NODE_01 is highlighted in this window. That sensor recorded a mean tilt of <NODE_02_tilt> deg."`).
4. **(iv) `iv_hedge_removed_certainty`**: Hedged wording (`"is consistent with"`, `"indicates simulated"`) removed and replaced with unhedged physical certainty (`"the ground has moved"`).
5. **(v) `v_invented_number_as_words`**: An invented but plausible numeric magnitude written out in English words rather than digits (`"about half a degree"`).
6. **(vi) `vi_contradictory_suggested_check`**: A `suggested_check` that contradicts the packet's diagnostic locus by asking the operator to inspect a node that has no anomaly (the quietest node with the lowest tilt, lowest piezo RMS, and zero missing packets, using its real quiet numbers while claiming it shows the primary anomaly).

## 3. Experimental Protocol & Freeze Guarantee

1. **Pre-Registration Commit:** This file (`docs/explainer_heldout_expectations.md` and `simulation/docs/explainer_heldout_expectations.md`) is committed **alone** before writing or running the held-out corruption generator or making any judge API calls.
2. **Deterministic Seed:** `20261125` (`6` corruptions per type across `6` types = `36` corrupted explanations, plus the `42` untouched controls = `78` items).
3. **No Guard Modification:** `simulation/canary_sim/explainer/guard.py` and `explainer_config.json` must **not** be altered in this step.
4. **Statistical Reporting:** Every catch rate and false-positive rate will be reported with both bootstrap 95% CIs and exact (Clopper-Pearson) 95% binomial confidence intervals (plus the $3/n$ rule-of-three upper bound for zero counts).
5. **Budget Cap:** Judge calls only (`36` new judge calls; the `42` untouched judge evaluations are already cached), keeping total prompt spend well under the **$1.00 USD** hard spend cap.
