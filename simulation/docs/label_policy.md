# Label Policy (FROZEN Specification)

> [!IMPORTANT]
> This document specifies the frozen label policy for **ProjectCanary-Sim** synthetic datasets. All data generated by the simulator adheres to this exact policy. Class labels live in a dedicated labels table (`window_labels.csv`) derived from the state timeline and telemetry fault metadata; they are **never** written into the underlying state timeline.

---

## 1. The Six Condition Classes

The system defines six mutually exclusive headline condition classes:

| Class | Description | Synthetic Source |
|---|---|---|
| `normal` | Undisturbed ground with benign confounders (ambient diurnal temperature drift, wind/vehicle vibration bursts, benign baseline tilt drift). Hard negatives. | Confounder engine (`confounders.py`) + null settlement |
| `gradual` | Slow Gaussian/elliptical ground subsidence basin developing over tens of seconds. Tilt slope persists indefinitely. | State timeline (`engine.py`) |
| `rapid` | Sudden, fast-moving subsidence basin developing over a short timescale (e.g. 5–10 s). Tilt slope persists indefinitely. | State timeline (`engine.py`) |
| `abnormal_vibration` | Sustained mechanical agitation and high-amplitude impulse bursts across $\ge 3$ nodes exceeding benign confounder margins. No ground subsidence. | Piezo model (`sensors.py`, `classes.py`) |
| `sensor_fault` | Hardware/sensor-level corruption on IMU or LiDAR hub (bias step, slow drift, stuck reading, isolated spikes, disconnect, implausible reading, motor stall, stale reading). | Fault injector (`faults.py`) |
| `comm_fault` | Telemetry link failure (packet drop bursts, node unavailability, high latency spikes, network-wide blackout). | Fault injector (`faults.py`) |

---

## 2. Windowing and the 50% Overlap Rule

- **Window Duration ($L$):** $5.0\text{ s}$
- **Hop Size:** $2.5\text{ s}$ (50% window overlap)
- **Overlap Fraction ($f_c$):** For class $c$ with active intervals $\{[a_i, b_i]\}$, the overlap fraction in window $[t_0, t_1]$ is:
  $$f_c = \frac{1}{L} \operatorname{length}\left( [t_0, t_1] \cap \bigcup_i [a_i, b_i] \right)$$
- **Active Threshold:** A class $c$ is considered **active** in the window if and only if:
  $$f_c \ge 0.50 \quad (2.50\text{ s of simulated time})$$

---

## 3. Transition Windows ("Touching" Policy)

When an event or fault starts or ends mid-window such that:
$$0.0 < f_c < 0.50$$
and no other class achieves $f_c \ge 0.50$:
- The window is assigned the label `"transition"`.
- Transition windows are **excluded** from standard window-level training and scoring matrices (via `trainable = (label != "transition")`).
- The window records the exact relative offset from the event onset:
  $$t_{\text{rel\_event\_start\_s}} = \frac{t_0 + t_1}{2} - t_{\text{event\_start}}$$
  This allows sub-window detection delay benchmarks during run-level evaluation.

---

## 4. Aftermath Handling

Different physical processes have different aftermath semantics:

### A. Basin Settlement (`gradual`, `rapid`)
- Ground subsidence is permanent: once the ground settles into a basin, the slope (tilt) and displacement remain present.
- **Rule:** The active interval extends from the onset time $t_{\text{on}}$ to the end of the simulation ($T_{\text{end}}$).
- All post-settlement windows are labelled with the basin class (`gradual` or `rapid`).
- Windows during the post-settlement period have `is_aftermath = 1`.

### B. Transient Faults and Abnormal Vibration (`abnormal_vibration`, `sensor_fault`, `comm_fault`)
- Sensor glitches, communication outages, and vibration events have defined start and end times $[t_{\text{start}}, t_{\text{end}}]$.
- **Rule:** The active interval covers only $[t_{\text{start}}, t_{\text{end}}]$.
- Once $t > t_{\text{end}}$, the condition clears. Following any transition window, subsequent windows return to `"normal"`.

---

## 5. Stress Set Labelling (Multi-Condition Runs)

In stress runs, multiple conditions occur concurrently (e.g. `gradual` settlement occurring during packet loss or sensor bias step).

### Priority Hierarchy
When multiple classes meet the $f_c \ge 0.50$ activation threshold in the same window, the single primary `label` is chosen by fixed physical priority:
$$\text{rapid} \succ \text{gradual} \succ \text{abnormal\_vibration} \succ \text{sensor\_fault} \succ \text{comm\_fault} \succ \text{normal}$$

### Secondary Condition Tracking
To prevent information loss:
- `label`: Primary priority class string (used by multi-class classifiers).
- `label_set`: Pipe-separated string of **all** classes meeting $f_c \ge 0.50$ (e.g. `gradual|sensor_fault`).
- `partial_set`: Pipe-separated string of classes with $0.0 < f_c < 0.50$.

## 6. Worked Examples

### Worked Example 1: 50% Overlap Rule
- **Scenario:** A rapid basin event begins at $t = 11.0\text{ s}$ and persists to run end ($t = 60.0\text{ s}$).
- **Window:** Window 4 spans $[t_0 = 10.0\text{ s}, t_1 = 15.0\text{ s}]$ ($L = 5.0\text{ s}$).
- **Intersection:** Event active in $[11.0, 15.0]$, duration $= 4.0\text{ s}$.
- **Overlap:** $f_{\text{rapid}} = 4.0 / 5.0 = 0.80 \ge 0.50$.
- **Result:**
  - `label`: `"rapid"`
  - `label_set`: `"rapid"`
  - `is_transition`: `0`
  - `is_aftermath`: `0` (active settlement ramp)

### Worked Example 2: Transition Window ("Touching")
- **Scenario:** Same rapid event starting at $t = 11.0\text{ s}$.
- **Window:** Window 3 spans $[t_0 = 7.5\text{ s}, t_1 = 12.5\text{ s}]$.
- **Intersection:** Event active in $[11.0, 12.5]$, duration $= 1.5\text{ s}$.
- **Overlap:** $f_{\text{rapid}} = 1.5 / 5.0 = 0.30$.
  - $0.0 < 0.30 < 0.50$. No other class active.
- **Result:**
  - `label`: `"transition"`
  - `partial_set`: `"rapid"`
  - `is_transition`: `1`
  - $t_{\text{rel\_event\_start\_s}} = (7.5 + 12.5)/2 - 11.0 = -1.0\text{ s}$ (window center is 1.0 s before event onset).

### Worked Example 3: Transient Fault Aftermath
- **Scenario:** A sensor `bias_step` fault is active from $t = 20.0\text{ s}$ to $t = 30.0\text{ s}$.
- **Window A:** $[t_0 = 22.5, t_1 = 27.5]$ $\rightarrow$ fully covered $\rightarrow$ `label = "sensor_fault"`.
- **Window B:** $[t_0 = 27.5, t_1 = 32.5]$ $\rightarrow$ fault active in $[27.5, 30.0]$ ($2.5\text{ s}$) $\rightarrow$ $f = 0.50$ $\rightarrow$ `label = "sensor_fault"`.
- **Window C:** $[t_0 = 30.0, t_1 = 35.0]$ $\rightarrow$ fault active in $[30.0, 30.0]$ ($0.0\text{ s}$) $\rightarrow$ `label = "normal"`, `label_set = ""`.

### Worked Example 4: Stress Set Dual-Condition Window
- **Scenario:** Run combines a `gradual` basin active from $t = 15.0\text{ s}$ onwards, and a `comm_fault` (packet blackout) active in $[20.0, 40.0\text{ s}]$.
- **Window:** Window spans $[t_0 = 25.0\text{ s}, t_1 = 30.0\text{ s}]$.
- **Overlap:**
  - $f_{\text{gradual}} = 5.0 / 5.0 = 1.0 \ge 0.50$
  - $f_{\text{comm\_fault}} = 5.0 / 5.0 = 1.0 \ge 0.50$
- **Priority Resolution:**
  - $\text{gradual}$ has higher priority than $\text{comm\_fault}$.
- **Result:**
  - `label`: `"gradual"`
  - `label_set`: `"gradual|comm_fault"`
  - `overlap_gradual`: `1.0`
  - `overlap_comm_fault`: `1.0`
